## 一、项目本体分析

### 1.1 要解决的核心问题

一句话：**为"处于结构性转折期的中国年轻失业毕业生"，把每日涌来的公开新闻，转成可执行的结构性判断，并且让这些判断可被证伪、可被追踪、可被复盘。**

拆成四个子问题：

| 子问题 | 本项目做法 |
|---|---|
| 信息过载：50 个源每天数百条，看不过来 | 云端 6 次/天抓取 → SimHash+Jaccard+URL 三重去重 → 时效半衰期评分 → 高/中/低/归档分级 |
| 看不懂外语源 | NVIDIA API 增量翻译（CI）+ OpenCode Zen 本地翻译（30条/6min） |
| 看懂了但不知道"对我意味着什么" | 双层身份传导研判：第一层普通公民（物价/安全/资产/政策），第二层失业毕业生（就业/技能/政策/避坑）+ 四维政治经济学诊断 |
| 判断完了就忘了，无法验证对错 | 71 节点假设树（mega/major/medium/small）+ 证伪判据 + 指标阈值 + ACH 竞争性假设矩阵 + 贝叶斯后验 + 周循环验证 |

### 1.5 本项目真正的独特性（三个"别人没有"）

1. **四维政治经济学分析框架**：积累制度 / 空间修正 / 国家-市场边界 / 阶级利益——这是本项目自创的分析本体，所有通用情报工具都没有。
2. **双层身份传导**：同一条新闻输出两层影响（普通公民 + 失业毕业生），并强制输出 18 个月行动窗口 + 避坑清单。通用工具只做"摘要 + 情感倾向"。
3. **假设树 + ACH + 贝叶斯 + Obsidian 闭环**：从"用户的一个想法"经 5 轮追问 → 观点卡 → 可证伪子命题 → 指标阈值 → 证据日志 → 竞争性矩阵 → 后验置信度 → 回写知识库。这条链路在开源世界里**没有完整对应物**。

## 四、可复用 / 可借鉴清单（按优先级）

### P0 · 强烈建议借鉴（补的是本项目的真实短板）

#### 1. 引入校准评分（Brier / Murphy 三分解）→ 学 Anamnesis

**问题**：本项目的 confidence 是 AI 在验证时直接输出的 `new_confidence: 0-1`，既没有基准真值，也没有校准度量。71 个假设全部 active、0 falsified，无法判断"这个 0.62 到底是过度自信还是保守"。

**建议**：
- 新增 `data/hypotheses/resolutions.jsonl`，记录每个已到期假设的**客观结果**（resolved: yes/no/partial + 结果日期 + 判定依据）
- 新增 `local/calibration.py`：算 Brier score，并按 Murphy 分解为 Reliability（校准）/ Resolution（分辨度）/ Uncertainty（题目本身难度）
- 仪表盘加一块"校准曲线"：把预测概率分桶（0-10%/10-20%…），对比实际命中率
- 关键价值：**能区分"校准好但没分辨力"和"分辨力好但过度自信"**——前者看着准其实没用（永远报基准概率），后者看着有洞察其实在亏钱

#### 2. 修复验证闭环 → 这是 Bug，不是设计

**问题（实测发现）**：71 个假设里 **64 个 deadline 为空**，而 `hypothesis_engine.get_due_hypotheses()` 的判定是 `if due and due <= today`，空期限直接跳过 → **验证循环几乎从不触发**。这正是"71 全 active、0 falsified"的直接原因。

同时 `verify_hypotheses.py` 的阈值判断是空实现：
```python
threshold = ind.get("threshold_support", "")
if threshold:
    support_count += 1        # ← 只检查"阈值字符串非空"，根本没比较数值
```
且 `FRED_SERIES` 里 `PPI / LPR / 稀土出口配额 / 碳酸锂现货价` 等大量映射为 `None`。

**建议**：
- `tools/fill_falsification.py` 扩成 `tools/fill_deadline.py`：对 deadline 为空的节点，按 `time_horizon_months` 或 indicators 的数据发布频率回填合理期限
- 重写 `verify_hypotheses.py` 的 `evaluate_hypothesis()`：把 `threshold_support/refute` 从自由文本解析成可执行的比较表达式（如 `" youth_unrate > 18"`），真正比数值
- 给 `FRED_SERIES` 的 None 项找替代源（PPI→NBS、LPR→央行公告页）

#### 3. 补事件聚类层 → 学 Meridian / ClueArk

**问题**：本项目只有"去重"没有"聚类"。2,152 条情报里，同一事件被 10 家媒体报道，现在会以 10 条独立卡片进仪表盘，而假设的 `evidence_log` 也会记 10 条重复证据。

**建议**：
- 新增 `tools/cluster_stories.py`：在 `refresh.py` 的去重之后、重建 dashboard_data 之前插入聚类
- 轻量方案（推荐，零外部依赖）：`sklearn.TfidfVectorizer`（中文用字符 2-gram）+ `cosine_similarity` 阈值切分 + 连通分量聚簇——纯本地、无 API 成本、不需要 embedding
- 重方案（可选）：接 embedding API + HDBSCAN，但需要新增白名单域名
- 产出 `story_id` 字段：仪表盘按事件折叠，假设的 evidence_log 按事件去重聚合 → **直接提升 ACH 矩阵质量**（现在的证据行是重复的新闻条目）

#### 4. ACH 补敏感性分析 → 学 ArkhamMirror

**问题**：`ach_matrix.py` 有诊断、有 LR、有贝叶斯更新，但缺 Heuer 方法论里最关键的一步——**敏感性分析**：哪些证据真正决定了排名？

**建议**：在 `bayesian_update()` 之后加 `sensitivity_analysis()`：
- 逐条移除/翻转载断据，重算后验，看 Top-1 是否变化
- 输出"诊断性最高的 3 条证据"和"最脆弱的假设"
- 落到 ACH 周报 markdown 里（Heuer 原话：ACH 的价值在于告诉分析师**下一步该去找什么证据**）

### P1 · 值得借鉴（收益明确，成本中等）

#### 5. 情报→假设匹配升级 → 学 RSSidian 的向量检索（取轻量版）

**问题**：`link_intel_hyp.py` 用硬编码 `DOMAIN_MAP`（10 个域的关键词表）做匹配，新假设必须手工加关键词，扩展性差。

**建议**：用 TF-IDF + 余弦相似度（与第 3 项共用向量化结果，边际成本≈0）替代关键词表，把假设的 `title + core_claim + rationale` 和情报的 `title + summary` 投到同一空间，取 top-k 相似度 > 阈值的做关联。保留 DOMAIN_MAP 作为兜底。

#### 6. Verdict 粒度从 3 档改连续分 → 学 LLM-as-a-Verifier

**问题**：`verify_hypothesis()` 的 verdict 是 `supported/partially_supported/refuted/inconclusive` 四档，斯坦福的实验显示离散评分在相近质量的候选项上**平局率高达 27%**。

**建议**：让裁判模型输出 1-20 的整数分 + 理由，映射回 verdict。改动只涉及 prompt 和解析，成本极低。

#### 7. 关键词过滤 DSL → 学 TrendRadar

**问题**：`sources.yaml` 的 keywords 是平铺列表，"命中任意一个"逻辑太粗。

**建议**：支持 `+必须词`（AND）、`!过滤词`（NOT）、`@N`（单组上限）、`/regex/`。约 30 行代码，写在 `cloud/clean_dedup_score.py` 或 `fetch_rss.py` 的关键词打分处。

#### 8. 高确信翻车高亮 → 学 Regret Ledger

**问题**：假设树面板没有"异常"标记，用户看不出哪个判断出了问题。

**建议**：在 `gen_dashboard.py` 的假设卡片上，对"置信度 ≥0.7 但被判 refuted"或"置信度断崖下跌 >0.2"的节点加红色边框 + 标记。同时引入结果归因字段（逻辑验证失败 / 执行变形 / 意外变量），避免因为纯运气不好而过度调低置信度。

#### 9. 宏观指标补数据源 → GDELT

**建议**：新增 `tools/fetch_gdelt.py`（加入 `verify_hypotheses.ALLOWED_HOSTS` 或 `tools/` 自己的白名单），抓国际侧结构化事件（CAMEO 事件编码 + 语气分），补 33 个 `scope:ci` 外国源在 CI 挂掉时的空缺。**只补国际侧，中文源继续靠金十/新浪/RSSHub**——GDELT 对中文源覆盖差的批评是一致的。

### P2 · 了解即可（不建议现在做）

| 项目/思路 | 判断 |
|---|---|
| Argdown 论证语法 | 让 Obsidian 假设页可机读，但本项目已有结构化 JSON，Markdown 只是渲染产物，收益 < 改造成本 |
| Squiggle 分布代数 | 把点置信度升级为区间，理论上更严谨，但对单人研判系统过重 |

| SpiderFoot / Maltego / Recon-ng | **不相关**：实体调查向，与宏观研判不是一个问题域 |

## 五、一句话总结

**轮子不用重造，但四个零件该换。**

- **采集 + 去重 + 翻译 + 四维研判 + Obsidian 集成** —— 这条链路在开源世界里没有完整对应物，本项目的四维框架和双层身份传导是独创资产，继续自己维护。
- **事件聚类、校准评分、敏感性分析、验证执行** —— 这四个环节有成熟方案做得更好，且都是**本项目当前的真实短板**（尤其"64/71 假设无 deadline 导致验证从不触发"是硬 Bug）。
- 建议落地顺序：**先修验证闭环（P0-2）→ 再加校准评分（P0-1）→ 然后事件聚类（P0-3）→ 最后 ACH 敏感性分析（P0-4）**。前三步做完，假设树才从"好看的展示品"变成"真正能积累判断力的资产"。
